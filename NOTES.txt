Porting SMF 1.1.21 to Go

Many folks interested in, for example, permacomputing, are heavily anti-coding
agent. I am interested in leveraging agents to do 'archival' work. 

1. All code gets a human reviewer (me)
2. The coding agent's role diminishes over time: it creates scaffolding that I
am ultimately responsible for maintaining
3. The artifact should not be unmaintainable garbage. 

The code produced is mediocre. It looks like translated PHP code. It is not
beautiful. But it is legible, and I can work on it.

Creating a "software artifact"

I decided to preserve the php-like stuff, like the routing, to minimize the
porting effort.

This was from an era where people used less software, so certain conventions
were not intuited. The help articles are extremely extensive and teach you hvery
basic things about the forum

The model of 'installing software' is goneA

Trimming down

A lot of the 'vestigal' features (calendar, karma, etc) are against my goal of
'a codebase that I can maintain solo'. I did not want to produce "AI slop", I
wanted to produce something I was happy with.
